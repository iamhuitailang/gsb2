# 动作状态机本地调试页

纯静态、零依赖、无需构建：直接双击 `index.html`（或 `python3 -m http.server` 后访问）即可使用。
针对“进了实机才发现动作切换太迟”的问题，用几何火柴人表示走路 / 刹停 / 起跳等关键姿态，
在本地把状态、动作时长、切换条件、打断/排队策略和输入时间线全部跑明白。

## 运行

```bash
# 方式一：直接打开
open debugger/index.html

# 方式二：本地静态服务
cd debugger && python3 -m http.server 8000
# 浏览器访问 http://localhost:8000

# 测试（仅需 Node）
node tests/engine.test.js   # 引擎行为与静态分析，47 项
node tests/smoke.test.js    # 页面初始化/交互冒烟，16 项
```

## 仿真模型要点

- **固定时间步 1/60s**：所有输入先量化成每 tick 的 `pressed / held / released` 网格，再驱动状态机。
  同一份 config + timeline 任意次运行、任意 seek 位置，结果完全一致。
- **条件原子**：按下沿 / 松开沿 / 按住中 / 未按下 / 状态持续≥N 秒 / 动作播完 / 无条件，AND 组合。
- **优先级**：同 tick 多条切换满足时取 `priority` 最大者；全部满足者都写进事件，便于复盘。
- **过渡（blend）**：切换后在 `blendDuration` 内从源姿态插值到目标姿态。
  - `interruptible=true`：过渡中可被新请求打断，新过渡**从当前视觉姿态**（当前插值结果）起步。
  - `interruptible=false`：新请求按 `blockMode` 处理——`discard` 直接丢弃并记录原因，
    `queue` 进入队列，过渡结束后用 `acceptGates`（缺省回退到 `gates`）重新判定是否受理，
    超过 `queueMaxWait` 超时丢弃。
- **循环边界**：在循环末尾仍按住的键，其松开事件回绕到 tick 0，保证跨循环复现。

## 三套预置配置

- **A · 基线**：长混合、不可打断、冲突请求直接丢弃——复现“切换太迟/输入被吞”。
- **B · 快响应**：短混合、关键过渡可打断、不可立即受理的请求排队——对照修复方案。
- **C · 问题配置**：在 walk 上故意加一条高优先级宽松条件，演示 lint 如何报出
  “某切换可能永远进不去（条件遮蔽）”。另含一个无入边的 `hurt` 状态演示不可达检测。

## 静态分析（lint）覆盖

不可达状态、源/目标状态不存在、按键引用不存在、空条件、条件遮蔽（高优先级且条件更宽松者抢先）、
有限动作播完后无出口（会卡在末帧）。
