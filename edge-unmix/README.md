# 边缘去底色工具（Edge Unmix）

本地运行的单页工具，修复“图标先贴在纯色底（典型为白底）上导出、再抠成透明 PNG”
导致的半透明边缘混色问题——这类图放到深色界面上，边缘会露出一圈底色。

- 纯前端、零依赖、零网络：双击打开 `index.html` 即可，图片不离开本机
- 原图只读：所有处理在内存 Canvas 中进行，导出为另存的新文件
- 核心算法在 `processor.js`，浏览器与 Node 共用同一套代码并带自动化验证

## 快速开始

```text
1. 双击打开 index.html（或 open index.html）
2. 点右上角“加载透明 PNG”，可多选；也可直接把 PNG 拖进窗口
3. 左侧选择“过去使用的底色”，调整边缘强度与低透明阈值
4. 主画布与底部预览条对比修复前后；单击像素查看通道详情
5. 需要保留的区域用“画保护区”涂起来
6. “导出当前 / 批量导出全部”，得到 *_unmixed.png 与 *_unmixed_note.txt
```

重新生成测试样本：

```bash
python3 -I make_samples.py
```

运行算法与端到端验证：

```bash
node test_processor.js          # 24 项算法级验证，无需浏览器
# e2e 需要本机 Chrome 与 puppeteer-core（开发依赖，不在本目录内）
```

## 算法与安全边界

事故模型与逆推：

```text
混色：  C_obs = C_true · α + Mat · (1 − α)
逆推：  C_true = (C_obs − (1 − α) · Mat) / α        α 通道保持不变
```

处理规则（对应界面里的统计与标记）：

1. **只处理半透明像素**（0 < α < 255）。
   - α = 255 的完全不透明像素一律不动，真实的纯白高光、白色文字不会被改；
   - α = 0 的全透明像素保持透明，不会被填入颜色或不透明度。
2. **保护区像素完全跳过**，输出与输入逐字节相同。
3. **逆推值裁剪到 0–255**。若按所选底色逆推出界，说明底色假设对该像素不成立，
   裁剪并标记“逆推越界”，绝不输出负值/反色。
4. **接近全透明时不强行恢复颜色**。8bit 混色有 ±0.5 量化误差，逆推要除以 α/255，
   误差被放大到 `127.5/α` 级（如 α=16 时最大约 8 个色阶），此时真实颜色在数据中
   已不可恢复。工具提供两种策略：
   - **邻色填充（默认）**：用周围高可信（α 高于阈值）像素的颜色平滑填充，α 不变，
     并在图上以红色斜纹标记，请重点复核；
   - **保留观测色**：完全不动该像素的 RGB。
5. **边缘强度**在“观测色 ↔ 完全校正色”之间插值，强度 0% 等于不处理。

## 界面能力对照

- 多亮度底色预览：底部预览条固定提供近白 / 浅灰 / 中灰 / 深灰 / 近黑五种底色，
  点击任一预览即把主画布切到该底色；“修复后 / 原图”同位置切换，按住 **B** 可临时对比。
- 像素检查器：单击任意像素，显示原图 RGBA、校正后 RGB、Δ 变化、是否保护区及
  可信度标签。取点按 `floor((屏幕坐标 − 平移) / 缩放)` 反算，放大后仍精确对应原图
  整数像素坐标。
- 多图复用：新加载的图继承当前设置；“当前设置应用到全部”一键复用，每张图仍可
  单独微调；设置通过 localStorage 持久化（图像本身不持久化，刷新需重新加载）。
- 导出：每张图输出修复后的透明 PNG 与一份纯文本说明（参数、像素统计、低可信
  提示），文件名加 `_unmixed` 后缀，原始文件不会被修改。PNG 由内置字节级编码器
  直接从 RGBA 写出（不走 `canvas.toBlob`），因此保护区与未处理像素能逐字节保留，
  不受浏览器预乘 alpha 存储的舍入影响。

## 已知边界

- 仅支持 8-bit RGBA PNG；索引色/16bit PNG 由浏览器解码后按 RGBA 处理。
- 底色必须选对：若边缘混入的不是纯色或颜色选错，逆推会出现大量“越界”标记，
  此时应以标记为信号调整底色，而不是相信输出。
- 邻色填充是视觉修复而非信息复原——低 α 像素的原始颜色客观上无法找回，
  红色斜纹标记的区域建议在真实深色界面上再人工过一遍。
